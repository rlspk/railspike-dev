# Railspike v0.3.0 beta 2

Extended effort estimates now default to enabled for new enrolled effort-study cycles. Each Step 1 option gets a complete scoped-cycle estimate; each planned stage gets a separate work estimate preserved through execution revisions and retrospective assessment.

## Changes and compatibility

- No separate extension opt-in is needed for a new enrolled cycle. Study enrollment itself remains optional, and debug mode remains independent.
- Mode precedence is explicit user override, recorded cycle state, applicable host policy, then the enabled new-cycle default. Disable estimates for a cycle or set a host opt-out policy for future cycles.
- Existing settings survive upgrades. Older cycles with no mode field recover their earlier opt-in behavior; explicitly enable them prospectively if desired. Missing historical estimates remain missing.
- Frozen R1, independent cycle totals, append-only histories and existing approval/commit requirements are unchanged. Estimates remain provisional relative judgments, not hours, measured labor or additive forecasts.
