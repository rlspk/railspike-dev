# Railspike v0.6.1-beta.1

Plans and handoff messages now share six writing rules: keep one idea per sentence, use consistent terms and concrete verbs, avoid long noun strings, name the relevant file or setting when it helps explain a decision, and use active voice.

The shared section includes a before/after example. Step 1, Step 2, Step 3 planning, Step 4 implementation, and one-shot instructions link directly to it. Original queries, quoted sources, and fixed snapshot and attribution formats are exempt.

## Compatibility and upgrade

This patch clarifies writing guidance. Approval gates, artifact requirements, branching, commit cadence, page limits, and no-code planning guardrails remain unchanged. It includes the changes already present in v0.6.0-beta.1.

Opt in through the product README upgrade procedure, targeting `v0.6.1-beta.1` and preserving local changes. Existing installations do not update automatically. Roll back through the same procedure to the previous beta `v0.6.0-beta.1` or stable `v0.4.0` while preserving host-owned records.

The beta is prepared from `feat/plain-language-plans`; publication does not merge it into main or change the default installation. Stable Latest remains `v0.4.0`.
