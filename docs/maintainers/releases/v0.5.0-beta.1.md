# Railspike v0.5.0-beta.1

Railspike now maintains a concise project concept inventory under the consuming project's `docs/concepts/` and lists concepts touched in staged plans and one-shot records.

- Inventory maintenance is lazy: create or update entries only for concepts touched by the current cycle. No project sweep, full-inventory audit, or historical-plan backfill.
- Entries contain a name, purpose, brief behavioral scenario and source paths. One file or several are supported.
- Plans identify concepts created, changed or used unchanged and proposed inventory updates. Authorized implementation updates and verifies affected entries with the corresponding work.
- No feature flag or activation prompt. Work with no relevant concept can say “none” and needs no inventory file. Concepts do not require a particular code architecture.

## Compatibility and upgrade

This beta adds project concept documentation and plan fields. The maintainer selected the v0.5.0 version line. Existing step approvals, branch rules and commit cadence remain unchanged; ordinary non-Railspike tasks are unaffected.

Use the existing reviewed install/upgrade process and explicitly select `v0.5.0-beta.1`. Preserve local edits and the installation source record. Begin inventory maintenance with the next cycle's touched concepts; no migration or comprehensive inventory generation is required. Roll back through the same process to stable `v0.4.0`; retain host inventory documents as user-owned project records.

The beta is published from `feat/concept-inventory`; `main` and the default install remain unchanged. Stable Latest remains `v0.4.0`. No host installations are upgraded automatically.
