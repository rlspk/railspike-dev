# Railspike v0.4.0 beta 2

You can now remove Railspike with one prompt to your coding agent. Your own plans stay in place.

- A new [Uninstall](https://github.com/rlspk/railspike/blob/5952bfddba579ca3e76bbf397e7a0a5bbf150785/README.md#uninstall) section in the README has a copyable prompt and step-by-step agent guidance. The agent:
  - identifies whether Railspike is installed as a copy or a submodule;
  - reports local edits before removing anything;
  - removes the installation, the optional `## Railspike` section of `AGENTS.md`, and the optional `.railspike_debug_on` marker;
  - stops and asks when the installation type is unclear (for example, a subtree).
- Your `docs/plans/` and all unrelated files are kept. Changes are left uncommitted for your review. For a submodule, the removal is staged, and empty submodule metadata and an empty `.gitmodules` are cleaned up.
- The Quick start now links to the Uninstall section. The same prompt appears on [railspike.dev](https://railspike.dev/).

## Merge and compatibility

Compared with `v0.4.0-beta.1`, this beta changes only `README.md` (21 lines added, 1 changed). No workflow instructions, approvals, artifacts, branch rules, or commit rules changed. The installation, update, and migration procedures are unchanged.

The maintainer explicitly requested this beta on the current product `main`, which already contains the change. As with beta 1, default installs from `main` already include it. The GitHub release is a pre-release; stable Latest remains `v0.1.0`.

## Update and recovery

Use the existing reviewed update process: select `v0.4.0-beta.2` from `https://github.com/rlspk/railspike` and verify the product commit above. Preserve local edits and the installation source record. No host installation is upgraded automatically. To roll back, use the same process to return to `v0.4.0-beta.1`.
