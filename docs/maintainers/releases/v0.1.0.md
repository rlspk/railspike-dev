# Railspike v0.1.0

First public release of Railspike: Markdown instructions for assessing solutions, defining requirements, planning stages, and implementing work with explicit approvals and verification records.

Product revision: [`579c0c13956be36c308e50df60b1849f9e213da6`](https://github.com/rlspk/railspike/commit/579c0c13956be36c308e50df60b1849f9e213da6).

## Workflow contract
- Separate, editable planning artifacts with explicit `Approved Step N` gates; Step 1 is optional.
- A feature branch, an initial approved-plans commit, and verification plus a summary and commit for each implementation stage.
- Durable enhancement-request records, renewed planning for changed scope, and distinct follow-up cycles with fresh approvals.
- Reviewed copies by default; submodules on explicit request. Project plans remain outside the installed product. Optional welcome guidance and workflow diagnostics retain their own consent and state rules.

## Compatibility and limitations
This is an evolving v0.1.0 baseline. Future changes follow the documented patch/minor/major categories; required approval, artifact, branch, or commit changes warrant a major version under the current policy. Read each release's notes before updating.

Railspike provides instructions, not technical enforcement of agent behavior or a safety guarantee. Installation inspection and fixture checks do not establish universal agent compatibility. No runtime, agent plugin, or automatic updater is included.

The release tag is **unsigned and annotated**. Revision verification uses the recorded commit and tag identities; it does not authenticate a cryptographic signer. Maintainer signing setup is deferred, and throwaway keys were excluded.

## Install, update, and recover
Use the [README at this revision](https://github.com/rlspk/railspike/blob/579c0c13956be36c308e50df60b1849f9e213da6/README.md#quick-start), selecting the `v0.1.0` snapshot or its exact commit for a reproducible installation. Inspect before adopting instructions, record the source revision, and follow the installed welcome.

For copies, preserve the installed tree and source record, reconcile local changes against a reviewed snapshot, and replace only after verification. For submodules, preserve the previous pointer and review the target revision before deliberately updating. The README's standard update block follows `main`; it does not pin a release automatically. Restore the saved copy or previous reviewed submodule pointer if an update is unsuitable; preserve unrelated project work. See the [recovery guide](https://github.com/rlspk/railspike/blob/579c0c13956be36c308e50df60b1849f9e213da6/docs/failure-modes.md).

Legacy FDP/`gulkily/railspike` installations need deliberate migration to `rlspk/railspike`, `RAILSPIKE.md`, and `docs/railspike`. No legacy entrypoint aliases are provided. Follow the README's source-migration guidance, retaining local edits and rollback material. Upstream development records/checks live in [railspike-dev](https://github.com/rlspk/railspike-dev); they are not installed with the product.
