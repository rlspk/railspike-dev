# Railspike v0.6.0-beta.1

One-shot implementations now follow this sequence:

1. Create a feature branch.
2. Write and commit the plan before implementation.
3. Implement and verify the change.
4. Commit the implementation together with the updated plan.

The plan and outcome record remain the same file. No intermediate planning approvals or artificial stages are required. Explicit no-commit requests take precedence, while retaining the branch and written plan. For separate product/development repositories, the host planning commit precedes product edits and the host completion commit records paired implementation revisions.

Agents must verify the planning commit rather than treat a written plan or attempted commit as sufficient. Resumed cycles with missing planning commits preserve existing work and disclose the omission; they commit the current plan before further implementation without inventing earlier history.

Step 1 now includes “Reminder: Now is a good opportunity to /new or /clear.” with the plan link only when the conversation contained discussion before the current Step 1 task. The reminder appears once, before approval, and never requires a reset.

This release also retains v0.5.0 beta work: lazy maintenance of touched concept entries and shared implementation standards for staged and one-shot execution, with optional host guidance for Direct work.

## Compatibility and upgrade

This changes the required one-shot commit sequence. The maintainer explicitly requested a minor version increment. Opt in with the reviewed upgrade procedure targeting `v0.6.0-beta.1`, preserve local changes, and follow the planning commit gate for new work. Existing already-started cycles follow the documented recovery rules; do not rewrite history to invent a planning commit.

Host guidance is not updated automatically; reconcile it separately with consent. Roll back through the reviewed process to stable `v0.4.0` while preserving host-owned records and inventories.

At the maintainer's explicit request, the feature branch has been merged into product `main`; default installations following main now include these changes. The beta tag itself remains a prerelease, and stable Latest remains `v0.4.0`. No existing host installation is automatically upgraded. This merge was explicitly authorized separately from version confirmation and publication.
