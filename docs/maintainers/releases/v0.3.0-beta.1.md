# Railspike v0.3.0 beta 1

This opt-in beta adds extended effort estimates for every Step 1 option and every stage in Steps 3 and 4. It also includes exact frozen-reference recovery improvements since `v0.2.1-beta.1`.

## Changes

- **Step 1:** each option gets a complete scoped-cycle estimate, a complexity driver and material uncertainty. Combined approaches receive a fresh estimate; the recommended-cycle checkpoint remains separate.
- **Step 3:** each stage gets a separately labeled work estimate covering its changes, verification, documentation and ordinary correction. Shared work has an explicit owner; the whole-cycle total is judged independently rather than calculated by summing stages.
- **Step 4:** preserve original stage estimates, append material entire-stage revisions before dependent work where possible, and record retrospective assessments separately at completion. Keep blocked/skipped/split histories and honest missing values.
- **Reference recovery:** recover exact historical source bytes, verify recorded hashes and retain portable host-local copies/provenance. A changed current document does not replace a frozen reference.

Extended estimates are optional: enable them for an established effort-study cycle or once through a standing host policy. Study enrollment alone does not enable the extension. Mode inheritance is independent of debug mode. Existing approvals, branching, commit cadence and frozen R1 meanings remain unchanged. Estimates are provisional relative judgments, not hours, measured actual effort, percentages complete or additive delivery forecasts.

## Opt in and rollback

Ask your agent to update the installed Railspike to tag `v0.3.0-beta.1` from `https://github.com/rlspk/railspike`, verify commit `c336536f88d1ce471b4f582a7d87203864f8526e`, preserve local edits and a recoverable prior state, and record the source/tag/revision. Identify the installation method before choosing the update procedure; leave host staging/committing to its normal workflow.

After the study/reference is established, ask: “Enable extended effort estimates for this cycle,” or explicitly enable the extension through the host's standing policy. Updating alone does not enroll or enable it. No host installations are automatically updated by this release.

Rollback uses the same reviewed procedure with the prior installed tag, such as `v0.2.1-beta.1`. Preserve host study records and estimate histories. Default installation continues to use `main`; stable “Latest” remains `v0.1.0`.

## Stable exit criterion

Review real opted-in cycles demonstrating every option/stage estimate, original-value retention through a discovery-driven revision, honest retrospective/missing-state handling, standing-mode inheritance and unchanged off-mode behavior without extra approval gates. Retain the earlier beta's known-user recovery criterion: demonstrate ordinary-entry recovery for the named user/environment with appropriate evidence. Maintainer comfortable-fit/study acceptance remains explicit and separate from technical completion; no validated forecast or measured-effort claim follows from publishing this beta.
