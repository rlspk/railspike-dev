# Railspike v0.2.0-beta.1 (pre-release)

A beta of Railspike's next minor version. **It is opt-in:** the default install and "Latest" stay at [`v0.1.0`](./v0.1.0.md).

Product revision: [`9774132db592c3bc9026163f50384f52376bac1c`](https://github.com/rlspk/railspike/commit/9774132db592c3bc9026163f50384f52376bac1c), based on the `v0.1.0` revision `579c0c13956be36c308e50df60b1849f9e213da6`.

## What changed
- **Step 2:** when a request names a known user or environment, Step 2 states that user's ordinary entry point and recovery condition (the mismatch or failure, an unaided next action, how to verify or retry, and the evidence). Evidence from a different supported platform does not satisfy it.
- **Step 3:** a stage replays each reported failure as acceptance evidence. The after-checklist rejects an installer or other-platform pass; manual guidance can be the accepted outcome.
- **Step 4:** checks are reported as passed, failed, blocked, pending, or inapplicable, with reproduced baseline failures identified. A focused pass is never an unqualified full-suite or user-outcome result, and the handoff opens with anything unverified.
- **Failure modes:** a new section, "Passing tests did not establish the user's recovery".

Instruction text only: six files, +12 lines, one line modified. The four-step structure, approval gates, branch and commit requirements are unchanged, so this is a minor version under the policy.

## Why a beta, and the evidence boundary
These changes came from reviewing recorded debug logs, mainly a case where installer tests passed on a supported platform while the known user's recovery stayed unusable. They were verified by **replaying recorded cases against the new wording**, not by running live agents, so their effect on agent behavior is unmeasured. The beta exists to get that evidence. Records: [plans and replay results](https://github.com/rlspk/railspike-dev/tree/main/docs/plans/debug_log_process_improvements).

Leave staging and committing to my normal project workflow.

Your agent follows the README's copied-installation update procedure. Local edits to files the beta changes are reported for you to resolve and are not overwritten.

## Roll back
Make the same request with tag `v0.1.0`. The recorded revision in `RAILSPIKE_SOURCE.md` shows which version is installed.

## Exit criterion
The beta is promoted to `v0.2.0` after at least one real planning cycle on an opted-in project, with debug mode on and its log reviewed, shows no unnecessary gates on work that names no user or environment and no missed recovery condition when one is named. Promotion merges this same commit to `main`. Corrections ship as `v0.2.0-beta.2`; a published tag is never moved.
