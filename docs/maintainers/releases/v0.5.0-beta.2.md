# Railspike v0.5.0-beta.2

Staged and one-shot work now use one shared implementation contract. One-shot reduces planning handoffs and consolidates records while retaining the same implementation standards.

- Inspect existing components, styles, helpers and API contracts before creating equivalents. Record source paths and reuse/extension decisions; justify necessary new components.
- Define completion through normal entry, end-to-end outcome and failure/retry recovery. Resolve material risks before dependent work.
- Verify affected consumers and applicable environments/dependencies, replay reported failures, and disclose missing evidence. Review the final diff for duplication, scope and documentation.
- Staged instructions and the one-shot template expose the same evidence requirements. Existing approval gates, branch rules and commit cadence remain unchanged.
- Installation welcome offers host-owned engineering guidance covering Direct work as well as Railspike. It preserves consent and existing host rules; Direct tasks do not automatically become Railspike cycles or study observations.

This beta also retains beta 1's lazy concept inventory: maintain only touched concepts in the host's `docs/concepts/`, without a project-wide audit or historical backfill.

## Compatibility and upgrade

Use the existing reviewed upgrade process and explicitly select `v0.5.0-beta.2`. Preserve local edits and source records. Follow the shared contract on the next entry/resumption, keeping existing approvals and history; no new planning round or artificial stages are required solely for this update. One-shot records gain explicit reuse, completion and final-review fields.

Updating the installed Railspike files does not update host `AGENTS.md` or `CONTRIBUTING.md`. Adopt or reconcile the suggested host engineering rules separately with consent. Roll back through the same reviewed process to stable `v0.4.0`; preserve host-owned plans, inventories and guidance.

Published from `feat/shared-implementation-standards`; `main` and the default installation remain unchanged. Stable Latest remains `v0.4.0`. No host installations are upgraded automatically.
