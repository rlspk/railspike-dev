# Railspike v0.4.0 beta 3

The post-install welcome now asks whether to add Railspike guidance to `AGENTS.md` as a question on its own, so the offer gets an answer instead of being overlooked.

- The welcome ends with one yes/no question, such as "Add this to AGENTS.md? (yes/no)", with nothing after it. The agent asks for your first task only after you reply.
- **Yes:** the agent adds or updates the guidance under the existing consent rules. It preserves unrelated `AGENTS.md` content and does not add a duplicate Railspike section.
- **No:** the agent leaves the file alone and doesn't offer again.
- **Anything else, such as a task:** the agent leaves the file alone, tells you in one line that the guidance was not added and that you can ask for it later, and carries on with what you said. It won't ask again in that session.
- The agent always states the result: `AGENTS.md: added`, `declined`, or `not answered`.
- A task you included with the installation request is still kept. It starts after the guidance question, and you aren't asked for it again.

The previous welcome put the offer and "What would you like to work on first?" in the same turn. It also told agents to treat an unanswered offer as declined without saying so.

## Merge and compatibility

Compared with `v0.4.0-beta.2`, this beta changes only `WELCOME.md` and two Quick start sentences in `README.md`. Workflow steps, approvals, artifacts, branches, commits, and the installation, update, and uninstall procedures are unchanged. The guidance text offered for `AGENTS.md` is unchanged, so existing Railspike sections remain valid.

Following the default beta policy, this beta is tagged on the unmerged product branch `feature/welcome-guidance-question`; `main` is not changed. Default installs from `main` still get `v0.4.0-beta.2` content. To try this beta, name the tag in an install or upgrade request. Stable Latest remains `v0.1.0`.

## Update and recovery

Use the existing reviewed upgrade process. Select `v0.4.0-beta.3` from `https://github.com/rlspk/railspike` and verify the product commit above. Preserve local edits and the installation source record. No host installation is upgraded automatically.

The welcome runs only after a new installation, so existing installations see no behavior change until someone reinstalls. To roll back, select `v0.4.0-beta.2` through the same process.

## Stable exit criterion

The criteria from beta 2 are unchanged. In addition, confirm in a live installation that the welcome asks the guidance question on its own and reports the outcome. Publishing this beta does not claim these criteria are met.
