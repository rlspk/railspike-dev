# Railspike v0.7.0-beta.1

## Plan length guidance

Steps 1–3 no longer have a "≤1 page" limit. Each step now has a soft length goal:

- Steps 1 and 2: about a three-minute read (about 600 words). Step 1 options get about 100 words each.
- Step 3: a text budget of about 200 words per stage, with no whole-plan limit. A stage that cannot fit its required fields in its budget is a split candidate, raised in the handoff like the eight-stage limit.

A new Plan length subsection in the Writing style section of `RAILSPIKE.md` holds the shared rule. Required content comes first, and navigation, debug state, effort fields and attribution never count toward a goal. Stage size ("about ≤1 hour or ≤50 lines") is unchanged. The README and Warning Signs describe the new goals.

## Debug log attribution

Each new debug log entry carries one attribution line under its timestamp and step, in the existing agent attribution format. Existing logs are not backfilled.

## Compatibility and upgrade

Both changes are backwards compatible. Approval gates, branching and commit timing are unchanged. Plans that met the old page limit also meet the new goals. This beta includes everything in stable v0.6.1.

Opt in through the README upgrade procedure, targeting `v0.7.0-beta.1` and preserving local changes. Existing installations do not update automatically. Roll back through the same procedure to stable `v0.6.1`, preserving host records.

Hosts in the effort study should date the change in their ledger before the first cycle that uses it. Estimate drift from original to cycle estimate may shift at that date.

The beta is published from `feat/plan-length-and-agent-field`, built on the `v0.6.1` commit. Publication does not merge it into main or change the default installation. Stable Latest remains `v0.6.1`.
