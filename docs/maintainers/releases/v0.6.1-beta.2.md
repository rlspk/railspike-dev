# Railspike v0.6.1-beta.2

Each staged planning approval now saves the approved plan before the agent drafts the next deliverable:

1. At the first approval, establish the host feature branch and feature folder.
2. Commit and verify approved Step 1, then draft Step 2.
3. Commit and verify approved Step 2, then draft Step 3.
4. Commit and verify approved Step 3, then begin Step 4 setup.

If Step 1 is skipped, branch/folder setup begins at Step 2 approval. Step 4 verifies existing planning commits instead of creating a duplicate planning commit. Implementation stages still have their own commits and summary updates.

Approval commits contain only the approved step, necessary organization/navigation changes, the cycle's existing debug log and authorized checkpoint study records. Unapproved drafts, implementation and unrelated changes stay out. Failed commits block dependent progression. Substantive revisions require renewed approval and a new commit; explicit no-commit requests retain the branch, written plan and recorded waiver.

## Compatibility and migration

This changes required branch, folder and commit timing. At the maintainer's direction, this continues the v0.6.1 beta series as beta.2. The major, minor and revision components remain unchanged. One-shot execution retains its existing sequence; transitions into staged work follow the new approval commit gate.

Opt in through the README upgrade procedure targeting `v0.6.1-beta.2`, preserving local changes. In ongoing cycles, verify existing approval content and commits. Disclose missing history and save currently approved plans before dependent work; never fabricate or rewrite older approval commits. Respect existing explicit no-commit overrides. In split repositories, save plans in the host and establish the product branch before product edits; no empty product planning commit is required.

Roll back through the same reviewed process to `v0.6.1-beta.1` or stable `v0.4.0`, preserving host records. Host installations do not update automatically. Publication uses `feat/approved-plan-commits`; it does not merge the branch, change default installation, or change stable Latest from `v0.4.0`. This includes the plain-language guidance in v0.6.1-beta.1.
