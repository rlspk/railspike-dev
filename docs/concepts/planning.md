# Planning record

**Purpose:** make the proposed outcome, scope, affected concepts, and verification reviewable before work proceeds.

**Operational principle:** in a staged cycle, the maintainer reviews the current plan and approves progression before the next step is drafted or executed. In a bounded one-shot cycle, the agent records the user's authorization and intended outcome before execution, then retains decisions and outcomes in that record. Both forms identify concepts touched and proposed inventory changes, and carry source-backed reuse decisions, completion/recovery conditions, risks, and verification evidence under the shared implementation standards.

**Where it lives:** [shared implementation standards](../../../railspike/docs/workflow/implementation_standards.md), [planning artifact rules](../../../railspike/RAILSPIKE.md#planning-artifacts), [Step 2](../../../railspike/docs/workflow/step2_feature_description.md), [Step 3](../../../railspike/docs/workflow/step3_development_plan_do.md), and [one-shot record](../../../railspike/docs/workflow/one_shot.md#record-template).

# Approval and scope boundary

**Purpose:** keep implementation within the work the user authorized.

**Operational principle:** approving a staged plan allows the next prescribed step; a bounded one-shot request permits execution within its recorded authority. If implementation requires expanded scope, the agent records the discovery and seeks the required renewed approval before dependent work. Updating a concept description does not authorize changing behavior.

**Where it lives:** [mode selection](../../../railspike/RAILSPIKE.md#choose-the-execution-mode), [enhancement requests](../../../railspike/RAILSPIKE.md#enhancement-requests), and [one-shot scope changes](../../../railspike/docs/workflow/one_shot.md#resumption-and-scope-changes).
