# Concept inventory

**Purpose:** retain concise descriptions of project behavior for later cycles to reuse.

**Operational principle:** when a cycle touches a concept, its plan identifies the concept and any needed inventory update. Authorized implementation updates that entry to match delivered behavior and checks it against the source, leaving unrelated entries alone. Work with no relevant concept needs no inventory file.

**Where it lives:** [shared concept guidance](../../../railspike/docs/concepts.md), [staged implementation](../../../railspike/docs/workflow/step4_implementation_do.md), and [one-shot workflow](../../../railspike/docs/workflow/one_shot.md).
